# Languages of the interface

## Why

Signaire serves the three sign languages of Switzerland, whose users speak French, German or Italian, plus English
for others. The interface comes in French first (the project's first users), and the four languages are kept
complete: a half-translated interface is worse than none.

## Design

- **Web**: the Spring `MessageSource`, bundles `messages.properties` (French, the base) and
  `messages_<lang>.properties`. The language comes from `?lang=` (kept in a cookie), then `Accept-Language`, then
  French (`LocaleConfiguration`). The help pages exist per language.
- **CLI**: one picocli resource bundle per command, following the JVM default locale (`LANG`, `-Duser.language`);
  unsupported languages fall back to French. Category, language, media and layout names are shown in the user's
  language and accepted in any of the four.
- **Exports**: labels in `export*.properties`, in the language of the request (the user's).
- **Tests**: every translation has the keys of the French bundle; tests run in French (`argLine`), and switch locale
  where they test translations.

## Decisions

- **French is the base bundle**: the project's working language; a missing key falls back to French, never to a key
  name.
- **The four languages change together**: a change to a French message comes with its three translations in the same
  commit; tests enforce the same keys everywhere.
- **No hardcoded user-facing strings**, in templates, controllers or the CLI.
- **CLI commands and options stay French**: see [Command line](cli.md).
- **`MessageFormat` rules**: messages rendered with arguments double their apostrophes (`''`); others don't.

## Open questions
